## 真实后端联调

第一次检查时本机后端未启动，前端代理返回明确的连接失败。2026-10-29 晚补做了一轮真实联调。

环境：本机 MySQL 8.4 + Redis（带密码）、`uvicorn app.main:app` 监听 8000、`npm run dev` 监听 4318、数据库已到 `e5b7d1c3a820`。账号 `demo@example.com` 通过注册接口创建（验证码直接写入 Redis，跳过 SMTP 与 VAPTCHA）。

用带 CDP 的无头 Chrome 驱动真实页面，结果：

1. 首页加载完成，右上角显示「后端已连接」。
2. 点侧栏账号入口打开登录弹窗，填入邮箱密码后提交，411ms 后侧栏显示昵称 `demo`。
3. 输入「用三句话说明 SSE 断线续传是怎么工作的」并回车，`aria-label` 从「发送消息」变「停止接收回答」再变回，共 4.1s 收到完整回答；Markdown、代码块、赞踩按钮渲染正常。
4. 侧栏「最近对话」列出 3 条历史，标题取自首轮提问；刷新页面后历史仍在，说明是从后端重新拉取而非内存残留。
5. 接口层另测：`POST /chat` 返回 `answer` 与 `usage{prompt_tokens:159, completion_tokens:2}`；`POST /chat/stream` 帧序为 `start → 46×delta → meta → done`。
6. 新接口 `POST /chat/regenerate/{message_id}`：帧格式与 `/chat/stream` 一致，原回答保留为 `seq=2`（仍是 `complete`），新回答追加为 `seq=3` 且 `parent_message_id` 指向前者。
7. 成本闸门在真实 Redis 中记账：`chat:rate:{uid}:{minute}` 计数随请求递增，`chat:tokens:{uid}:{yyyyMMdd}` 累计 592，在途 ZSET 请求结束后清空。
8. `GET /metrics` 输出 `chat_turns_total{outcome="complete"}`、`chat_turn_duration_seconds`、`chat_first_token_seconds` 等指标。

仍未验证：SMTP 真实发信、VAPTCHA 真实票据（需要 HTTPS 页面与平台侧白名单）、公网部署、浏览器视觉细节（无头截图只覆盖桌面宽度）。

`npm test` 19 项在本机 Node 22.22.2 下全部通过。
